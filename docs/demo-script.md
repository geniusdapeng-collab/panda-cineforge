## 一、产品与客群深度分析

### 1.1 产品本质

WorkLoom 熊猫电商运营系统不是工具，是**一支住进卖家组织的数字员工军团**：
- 电商全场景运营：选品算账 / 刊登内容 / 广告投放 / 客服售后 / 供应链 / 对账税务 / 合规风控
- 闭环：目标 → 执行 → 围栏裁决 → 留痕 → 复盘沉淀
- 人机权责：AI 提案、人拍板（围栏 R1–R30 + 五级审批 + 哈希链可追溯）

### 1.2 目标客群（首垂直：电商多平台卖家）

| 客群 | 画像 | 最痛的点 | 买单动机 |
|---|---|---|---|
| 单平台多店腰部卖家（年营收约 3000 万） | 小团队，3-8 家店扎堆 1-2 个平台 | 操作岗人力吃紧、客服响应慢、广告烧钱没谱 | "一个人管十几家店，还比代运营便宜" |
| 国内多平台大卖 | 多平台全线作战，有运营总监无中台 | 各平台数据孤岛、大促手忙脚乱、差评救火 | "总部级经营中台，每家店都配得上" |
| 跨境多平台超级大卖集团 | 国内+跨境两军，多币种多仓多税号 | 欧美白天=中国深夜没人盯盘、VAT/汇损/合规风险 | "24 小时跨时区经营，睡后也在赚钱" |

**尖叫公式** = 看得见的经营数字（归因到钱）× 不用操心的过程（军团全包）× 我说了算的安全感（人拍板）

### 1.3 客户疑虑与剧本应答

| 疑虑 | 剧本中的应答场景 |
|---|---|
| "AI 做的投放能看吗" | 广告幕：ACoS 连续 3 天爆表，利润保险丝自动降预算 30% 并请示 |
| "会不会乱降价/乱承诺" | 围栏幕：降价超 10% 挂起待审、毛利红线物理阻断、涉费承诺必审 |
| "数据是不是真的" | 归因幕：五元哈希链 + 验链 + 全模拟运行态横幅（坦诚是演示数据） |
| "夜里谁盯欧美盘" | 夜班幕：多语言客服中心 22:00 接棒、黑五跨时区作战零漏接 |

## 二、演示剧本（四幕，15-20 分钟）

### 序幕 · 震撼开场（集团经营简报，30 秒）
- **台词**："熊猫优选集团 14 家店、13 个平台，昨天 GMV 折合人民币 3,100 万；13 平台账单对账连续 30 天零差错——财务今早什么都没做，多平台对账师自己核完了 9.6 万单。"
- **画面**：14 店铺矩阵看板 + 对账零差错 + 差评 2 小时 SLA 100% 指标。

### 第一幕 · 军团在干活（经营剧场 + 实况字幕，3 分钟）
- **台词**："你看，地板上是它的 82 个数字员工——英语客服组 3 秒回买家，素材工场刚出了 20 张主图，竞对雷达在盯跟卖。底部这条字幕，是它实时在干的事。"
- **画面**：熊猫运营中心四层（国内战区/跨境战区/中台楼层/客服中心）+ 全中文实况字幕滚动（刊登/调价/广告投放/会话应答）。
- **数据点**：1 工作中 · 2 请您定 · 78 待命。

### 第二幕 · 你拍板，它执行（围栏审批 + 决策对话，5 分钟）
- **台词**："它不会擅自降价。拼多多价格倒挂 17%，多平台价格守护提请全渠道对齐，附带毛利测算；亚马逊 ACoS 爆表，利润保险丝已自动降预算 30%，就等你点头确认——你点批准就执行。"
- **画面**：L4 审批卡 ×3（价格倒挂/ACoS 熔断/紧急采购）→ 集团CEO 视图请您决策 → 右侧 AskRail 剧本对话（"有什么要拍板的？"→ AI 列清单）。
- **关键**：AskRail 不是空的——首开即见老板与 AI 的完整经营对话（问询→审批→派单→复盘）。

### 第三幕 · 买家被接住了（买家服务前台 + 夜班，4 分钟）
- **台词**："美国买家半夜发截图问'订单怎么显示异常'，多模态客服看懂截图 3 秒就答了，还顺手查了物流。你睡着的时候，夜班班组接了 1.8 万条会话，一条没漏。"
- **画面**：C 端聊天历史（截图识别/尺码咨询/退款自助问答）→ 实操发消息秒回 → 夜班频道全中文行动流。

### 第四幕 · 算清每一块钱（SKU 损益 + 归因复盘，3 分钟）
- **台词**："月底你只需要看这本账：每个 SKU 的货品/佣金/广告/物流/退货/税费全拆，哪条广告计划亏的、哪个平台佣金涨的——全在链上，可回放、可验真。"
- **画面**：SKU 损益账本 + 月度归因战报事件 + 节拍控制台（晨报/偏差扫描/熔断巡检/集团决策包）。

### 收尾 · 一句话
> "您只做三件事：定方向、拍板、收钱。其他的，军团全包。"

## 三、剧本 → 运行模拟态数据映射（已落地清单）

| 剧本元素 | 数据载体 | 实现 |
|---|---|---|
| 集团战报数字 | `account_metrics` + 归因事件 | `pnpm db:seed`（14 店铺×30 天经营流水+月归因事件） |
| 客服秒回场景 | `ask.answer` 事件（真实问答台词） | seed / seed-boost |
| 订单/广告/售后/财务流水 | `order.*`/`ad.*`/`aftersale.*`/`settlement.*` 事件（六条流水线，勾稽差异≈0.3%） | seed |
| L4 审批三件套 | `approvals`（价格倒挂/ACoS 熔断/紧急采购，完整 snapshot+CEO 意见+依据链） | seed-boost |
| **AskRail 对话剧本** | `apps/web/src/lib/demo-conversation.ts`（电商四幕对话） | StarRing 首开装载（本文件同源） |
| **C 端聊天历史** | `apps/webc/public/service-front.config.json` 的 `demoHistory`（截图识别/尺码/退款问答） | ChatPage 无缓存时装载 |
| 夜班行动流 | `night.*` + 运营事件（夜班频道中文展示） | 种子 + display 映射层 |
| 实况字幕 | 近 48h 高密度事件 → LiveTicker | seed-boost |

**校验口径**：以上每个场景在 `PREVIEW_CHECKLIST.md` 有对应验证点；UI 变更必须实机截图核对。

## 四、续写纪律

1. 新场景先进本文（剧本先行），再落数据；
2. 数字必须全链路一致（战报卡=事件=对话台词=种子注释），改一处全改；
3. 每个行业复制时，先写该行业的 demo-script，再写 seed-boost。
