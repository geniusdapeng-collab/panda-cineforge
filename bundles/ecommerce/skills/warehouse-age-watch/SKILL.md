# 库龄监控与处置

## 一、何时调用
- cron 每日 04:30 全仓（4 国内仓+7 海外仓+FBA）库龄分层计算。
- 库龄跨过 90/180/270 天阈值事件触发分级处置流程。
- 长期仓储费账单到账触发复核。

## 二、输入契约
- 全仓 SKU 批次入库日期、在库数量、近 90 天动销。
- 仓储费率表（含长期仓储费阶梯）、清仓渠道价卡。
- 毛利红线参数（R2）与处置渠道清单。

## 三、执行步骤（操作手册）
1. 库龄五层分层：0–30 健康 / 31–90 关注 / 91–180 预警 / 181–270 处置 / 270+ 紧急。
2. 90 天预警：生成 SKU 清单推送运营，要求限期给出动销方案（促销/捆绑/站外清货）。
3. 180 天处置：强制进处置流水线——清仓定价测算（毛利红线内最大折扣，过 R2）→ 多渠道清仓分发（Outlet/站外 Deal/批发渠道）。
4. 270 天紧急：对比"继续仓储费 vs 弃置/移除 vs 折价清仓"三方案经济账，生成裁决卡。
5. 处置执行与结果回写：回收金额、处置损失计入 SKU 损益账本（联动 sku-profit-ledger）。
6. 月度库龄结构报告反哺备货模型：库龄恶化快的品类下调首单量。

## 四、边界与围栏
- R6：周转 >60 天库存的清仓预案 review；R2：处置定价不得击穿毛利红线（清仓特例须 review 留痕）。
- 弃置/销毁属资产减记，必人工确认（对齐 R23 高危动作纪律）。
- 不因库龄压力触发刷单清库存等违规动作，R11 直接 block。

## 五、与其他技能的协作
- 清仓定价联动定价域 margin-guard/clearance-pricing；补货闸门供 fba-replenish（180 天+禁补）；损失落账 sku-profit-ledger；现金回收进 cash-sandbox。

## 六、验收用例
- 正常：库龄 92 天 SKU 进预警清单并收到动销方案任务卡。
- 异常：库龄 272 天 SKU 输出"弃置 vs 移除 vs 清仓"三方案裁决卡，弃置动作停在人工确认。

## 七、门道出处
- 非★技能。来源：死因2·库存积压（270 天强制移除、长期仓储费涨 128%）+ 门道⑥库龄仪表盘。
