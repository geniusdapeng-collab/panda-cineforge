# 动态调价竞对联动

## 一、何时调用
- 事件驱动：竞对调价告警（competitor-product-track 联动）、库存压力阈值、高需求时段信号。
- cron 每 2 小时扫描调价机会窗。

## 二、输入契约
- 触发信号：类型、来源事件 ID、受影响 SKU 清单。
- 价格矩阵四价锚点（当前/保底/目标/竞对价）与库存深度、SKU 角色分层。
- 损益瀑布（margin-guard 口径）、价保期登记。

## 三、执行步骤
1. **定位 SKU**：动作=接收触发信号并定位受影响 SKU 与渠道单元格；产出物=受影响清单；回执=信号来源事件引用。
2. **读锚点**：动作=从 pricing-matrix 读取四价锚点与库存深度；产出物=锚点快照；回执=矩阵快照哈希。
3. **走决策树**：动作=竞对降价→先判角色（引流款跟至不亏线/利润款不跟转赠品防守）；库存>45 天销量→阶梯下探；需求高峰→上浮至目标价；产出物=调价候选方案；回执=决策树路径记录。
4. **测算影响**：动作=测算每档拟调价的净利影响与销量弹性预估；产出物=测算表；回执=过 margin-guard 闸门回执（R2）。
5. **围栏分流执行**：动作=单日降幅 ≤10% 且不触红线 auto 执行；>10% 进 review；价保期 SKU 自动跳过（R13）；夜班窗口仅 ≤3% auto（R17），其余挂起（R16）；产出物=改价指令/审批卡片；回执=平台改价 API 回执，无回执标「未核实」。
6. **效果回写**：动作=执行后 T+3/T+7 跟踪转化与毛利变化，回写调价模型；产出物=效果回写记录；回执=对比数据切片。

## 四、边界与围栏
- 绑定 R1（单日降价>10% 挂起待审）、R2（毛利红线 block）、R13（价保期禁改 block）、R16/R17（夜班白名单与 ≤3% 幅度）。
- 绝不做什么：绝不突破保底价与红线；绝不调价保期 SKU；绝不执行无 before/after/basis 三要素留痕的调价。

## 五、与其他技能的协作
- 上游：pricing-matrix（锚点）、competitor-product-track（竞对信号）、price-band-position（卡位建议）。
- 闸门：margin-guard 前置校验；赠品防守方案联动 gift-strategy；效果数据进 biz-dashboard。

## 六、验收用例
- 正常路径：竞对同款降价 12% → 2 小时内引流款跟价（≤10% auto 执行），利润款生成"不跟价+赠品防守"review 卡片，两类动作均留痕。
- 围栏触发：价保期内 SKU 命中调价信号 → 自动跳过并记录 R13 命中；夜班涨幅 5% → 挂起待审。
- 异常路径：改价 API 无回执 → 标「未核实」+ IM 告警，不宣称完成。

## 七、门道出处
- 门道③定价纪律（报告一调价频次痛点）：人工响应竞对平均滞后 24–48 小时；自动调价把响应压到 2 小时内，且围栏保证"快"不以"破线"为代价。
