# 六步决策建议书

## 何时调用
- 事件驱动：L4/L5 级审批路由升级事项——重大备货、新平台入驻、大额预算追加、战略级定价调整。
- 老板手动发起任意决策议题。
- 预算/采购触发 R20 升 L4 人批时自动附带本建议书。

## 输入契约
- 决策议题描述：背景、选项范围、时限要求。
- 经营数据：相关 SKU/店铺损益、现金流预测、库存深度。
- 组织记忆：pattern 类历史相似决策及结果（pgvector 语义检索）。
- 市场数据：类目规模、竞品格局、政策风险。

## 执行步骤
1. **情报收集**。动作：汇总议题相关的损益数据、市场数据、历史同期表现。产出物：情报包。回执：数据源清单与快照哈希。
2. **案例回忆**。动作：pgvector 语义检索组织记忆中相似决策案例及其事后结果。产出物：案例对照表（含"上次这么干的结果"）。
3. **多方案生成**。动作：产出 2–3 个候选方案，各附财务测算（投入/预期回报/回本周期）。产出物：方案卡。
4. **红队挑刺**。动作：独立 Agent 对每方案列失败剧本与尾部风险（≥3 条/方案）。产出物：风险清单。
5. **影响预估**。动作：测算对现金流/库存/账号安全的连锁影响（含最坏情形）。产出物：影响矩阵。
6. **建议书输出**。动作：结构化建议书进 review-console，附推荐方案与理由；六步中间产物全部留痕可回放。回执：建议书 ID+审批路由。

## 边界与围栏
- 绑定 **R30（高危审批超时）**：L4/L5 事项不过期不自动放行，超时升级而非放行。
- 数字CEO 只产出建议书，决策权永远在人；任何"系统代批"路径不存在。
- 涉及资金支付的部分仍受 **R20** 约束，建议书不构成付款授权。

## 与其他技能的协作
- 数据输入：sku-pl、cash-sandbox、budget-watch。
- 触发后联动：批准后由对应技能执行（如 new-shop-launch、purchase-order-auto）。
- 决策结果与偏差回写组织记忆，供 board-report"决策回放"章节引用。

## 验收用例
- 发起"是否入驻 Temu 半托管"：建议书含 ≥2 方案、每方案红队风险清单 ≥3 条、现金流影响测算，全程留痕可追溯。
- 超时未批：系统升级提醒而非自动放行。
