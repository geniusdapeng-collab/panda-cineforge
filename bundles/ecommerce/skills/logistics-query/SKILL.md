# 物流查询自助

## ① 何时调用
- 售中物流意图会话（查件/改地址/催发货）实时触发。
- 物流轨迹异常事件（滞留 >48h/破损签收/错分/超期未更新）主动触发安抚触达。

## ② 输入契约
- 会话上下文卡；物流官方 API（轨迹查询/拦截工单）；ERP 订单状态接口；店铺承诺发货时效表；快递侧工单接口；补偿方案配置。

## ③ 执行步骤
1. **意图三分**：查件/改地址/催发货。产出物：意图标签。回执：混合意图拆分子任务分别处理。
2. **查件**：调物流 API（执行面 L1 零 token 主路径）取最新轨迹，合成「当前位置+预计送达+异常提示」应答。产出物：轨迹应答卡。回执：API 失败标「未核实」，不得编造轨迹。
3. **改地址**：校验订单状态——未发货→ERP 直接改 auto；已发货→生成快递拦截工单+告知成功率与费用，不承诺必成。产出物：改址回执或拦截工单号。回执：写动作仅未发货单 auto。
4. **催发货**：核对承诺时效——未超期给时效安抚；已超期升级工单并附补偿方案选项。产出物：安抚应答或超期工单。回执：补偿 ≥¥500 触发 R10。
5. **异常件主动服务**：轨迹异常判定后先于买家发问触达（「已为您联系快递核实」），同时向仓储/快递派跟进工单。产出物：主动触达记录+工单号。回执：闭环跟踪至签收或理赔，全程节点留痕。

## ④ 边界与围栏
- R10（review）：物流理赔/补偿 ≥¥500 必人审。
- R22（review）：不向买家展示内部仓配成本信息；买家 PII 出域过脱敏网关。
- 轨迹数据只信官方 API；已发货改址只做工单不做承诺。

## ⑤ 与其他技能的协作
- 上游：service-front-copilot 路由；超期升级：aftersale-defender（SLA 雷达）；理赔升级：dispute-escalation；数据出口：logistics 域复盘与 reputation-report 口碑交叉。

## ⑥ 验收用例
- 订单轨迹 48 小时未更新 → 系统在买家咨询前主动触达安抚并生成快递核实工单（含工单号回执）。
- 买家要求改已发货订单地址 → 告知拦截方案、成功率与费用，不承诺必成，工单留痕。
- 物流理赔 ¥800 → R10 挂起 → 审批卡片含 RuleImpact(R10, review)；API 超时 → 标「未核实」不答轨迹。

## ⑦ 门道出处
- 报告一·售中环节：物流查询约占售中会话大头、单会话 2–5 分钟、客服日均重复查询数十上百次——AI 替代已过半，真正价值在异常件主动化：在买家来问之前先开口，把投诉消灭在酝酿期，把人工从日均百次复制粘贴中彻底解放。
