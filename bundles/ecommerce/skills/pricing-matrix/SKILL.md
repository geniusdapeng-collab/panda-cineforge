# 价格矩阵

## 一、何时调用
- cron 每日 04:30 全量刷新价格矩阵。
- SPU 主档成本变更、平台费率调整、新店铺开通等事件驱动即时重建。
- 人工圈选任意 SKU/店铺实时重算；任何调价类技能执行前必须读取本矩阵取锚点。

## 二、输入契约
- SPU 主档：成本基线、损益瀑布参数（货品成本/佣金/物流/退货损耗/税费）。
- 店铺与渠道清单：天猫/拼多多/抖音/京东/亚马逊/Temu/TTS/独立站。
- 大促日历与价保期登记；竞品价格带地图（competitor-product-track 产出）。
- 输入数据须带快照时间戳，缺失科目标「未核实」不得用估值补齐。

## 三、执行步骤
1. **读主档**：动作=从 SPU 主档读取成本基线与损益瀑布参数；产出物=SKU 成本基线表；回执=主档读取回执+参数哈希，缺档 SKU 列入异常清单。
2. **展开单元格**：动作=按"店铺×SKU×渠道"展开定价单元格，逐格写入当前价/盈亏平衡价/保底价/目标价/价保锁定期；产出物=四维价格矩阵；回执=单元格写入计数与覆盖率。
3. **前推 90 天日历**：动作=为每格前推 90 天价格日历，标注大促节点、季节曲线、价保截止日与可调价窗口；产出物=90 天价格日历层；回执=日历节点清单。
4. **叠加竞对地图**：动作=与竞品价格带地图叠加比对，标红失守格（低于保底价/跨平台倒挂/偏离卡位）；产出物=失守格清单；回执=标红格数+判定依据。
5. **出日报**：动作=生成《价格矩阵日报》：异常格清单+建议动作；产出物=日报；回执=推送记录。
6. **快照入事件库**：动作=矩阵快照哈希写入事件库；产出物=快照哈希；回执=事件 ID，作为一切调价围栏的判定基准。

## 四、边界与围栏
- 绑定 R1（单日降价>10% 的单元格写入挂起待审）、R2（低于"货品成本×1.15"的格标 block）、R13（价保期锁定的单元格禁止任何写动作）。
- 绝不做什么：绝不直接执行调价（执行走 dynamic-reprice）；绝不允许业务侧私自维护价格副本；绝不覆盖价保锁定格。

## 五、与其他技能的协作
- 下游：dynamic-reprice、promo-planner、price-parity-watch、fx-reprice、clearance-pricing 均以本矩阵为唯一事实源。
- 上游：spu-master-data（成本）、sku-pl（损益瀑布）、competitor-product-track（竞对价）。

## 六、验收用例
- 正常路径：构造 3 店铺×20 SKU×4 渠道数据 → 输出含保底价与价保锁定的完整矩阵+90 天日历。
- 围栏触发：某 SKU 拼多多价跌破保底价 → 该格标红并生成 R2 block 记录。
- 异常路径：SPU 主档缺成本科目 → 标「未核实」、该 SKU 列入异常清单、不出建议价。

## 七、门道出处
- 门道③定价与促销（蓝本 pricing-matrix 电商化）：把"哪个店哪个 SKU 今天该卖多少钱"从人脑升级为可巡检、可回放的总账，是定价围栏的地基。
