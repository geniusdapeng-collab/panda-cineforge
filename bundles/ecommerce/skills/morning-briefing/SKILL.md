# 集团晨报

## 何时调用
- cron 每日 08:30：夜班班组自治窗口（22:00–08:00）结束后自动触发。
- 老板手动 @数字CEO"现在出晨报"时即时触发（不等 08:30）。
- 夜班期间发生重大 P0 事件（如 R23 安全禁区熔断、账号绩效越限）时，不等晨报即时推送单条告警，晨报中再汇总。

## 输入契约
- 五元事件库（workdata）：夜班窗口内全部动作回执（Receipt），含 actor/action/context/rule_impact/result。
- 经营指标快照：昨日 GMV、毛利、ACoS/TACoS、退货率、库存周转、8 周现金流缺口。
- 待审批队列：review-console 中全部挂起项及其围栏规则号。
- 巡检分级结果（inspection）：P0/P1/P2 分级标签，防告警风暴。

## 执行步骤
1. **聚合事件回执**。动作：拉取夜班窗口全部事件，按 actor（数字员工）×action 去重合并同类项。产出物：原始事件清单。回执：记录聚合输入的事件 ID 区间与哈希。
2. **三栏归类**。动作：已完成（夜间自治执行成功项，附 Receipt）/ 待审批（review 挂起项，标注 rule_id 与建议手势）/ 需介入（block 与异常项，附根因摘要）。产出物：三栏草稿。回执：每条注明来源事件 ID。
3. **分级排序与折叠**。动作：每栏按 P0>P1>P2 排序，P0 置顶；合计 >20 条时 P2 自动聚合折叠为"另 N 条常规项"。产出物：≤20 条晨报正文。
4. **附核心指标速览**。动作：生成六指标一行速览，越限项标红黄灯。产出物：指标卡片。
5. **推送与升级**。动作：生成 IM 原生卡片推送老板移动端，待审批项附"一键批准/一键派单"手势；08:30 未读则 09:00 升级提醒（电话/短信通道）。产出物：推送回执。回执：送达与已读状态写事件库。

## 边界与围栏
- 绑定 **R30（高危审批超时）**：待审批项不过期自动放行，超时只升级提醒绝不代为批准。
- 只读+呈现：晨报本身不执行任何写动作；夜间已自治执行的动作用 Receipt 展示，不回溯改判。
- 条目 ≤20 条为呈现纪律，超出必须聚合折叠而非截断 P0/P1。

## 与其他技能的协作
- 输入依赖 biz-dashboard（指标速览数据源）、night-ops-suite（夜班回执）。
- 待审批项点击跳转 decision-brief 建议书或对应业务技能的审批卡片。
- 晨报中"需介入"项自动建工单路由到 incident-postmortem。

## 验收用例
- 模拟一夜班产生 47 条事件，08:30 晨报应输出三栏合计 ≤20 条、每条标注 rule_id，P0 项置顶且附"一键派单/一键批准"手势；P2 折叠为聚合行。
- 老板 09:00 未读 → 升级提醒发出且事件库留有升级回执。
