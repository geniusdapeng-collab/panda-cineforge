# 口碑周报

## ① 何时调用
- cron 每周日 20:00 生成。
- 口碑重大事件（评分骤降/舆情苗头/差评聚集）触发专项加刊。

## ② 输入契约
- 本周新增评价/评分变化/问答区活跃度；差评处置 SLA 达成数据（review-defense-window）；会话情绪分布（sentiment-alert）；售后工单口碑关联；质检违规数据（service-qc）；围栏运行日志（R9/R10/R12 触发与处置）。

## ③ 执行步骤
1. **数据归集**：跨域口碑数据汇总快照。产出物：数据快照（哈希入链）。回执：快照可回放，缺数标注「未核实」。
2. **三视角分析**：店铺视角（口碑净值排名与变化）、SKU 视角（口碑红黑榜 TOP10）、平台视角（各站点健康度）。产出物：三张榜单。
3. **归因交叉**：差评归因×客服质检违规×售后工单类型三维交叉，定位「哪个环节在制造差评」。产出物：交叉分析表。回执：交叉结论附原始记录索引。
4. **围栏运行统计**：R9/R10/R12 触发与处置（SLA 达成率/升级率/驳回原因分布）。产出物：围栏统计节。
5. **行动清单**：TOP5 口碑风险点各附整改任务卡（路由到对应班组），核销上周任务卡。产出物：≤5 张任务卡+核销表。回执：任务卡可溯源原始评价/工单。
6. **归档**：入组织记忆 pattern 类，供月度经营分析与数字CEO调用。产出物：归档记录。

## ④ 边界与围栏
- R22（review）：买家与坐席个人信息脱敏后入报告；只读分析，不直接执行业务动作。
- 数据快照哈希入链；报告结论须附数据出处。

## ⑤ 与其他技能的协作
- 联合出品：service-qc×reputation-manager；数据源：review-defense-window/review-asset-mining/sentiment-alert/aftersale-defender；任务卡出口：各域班组与质量闭环 quality-feedback；上层：数字CEO经营分析。

## ⑥ 验收用例
- 给定一周模拟数据 → 周报含三视角榜单、差评归因×质检交叉分析表、围栏 SLA 统计节与 ≤5 张任务卡，每张卡可溯源原始评价/工单。
- 报告中无明文买家 PII（脱敏校验通过）；数据快照哈希可回放验证。
- 评分骤降事件 → 触发专项加刊，非等到周日。

## ⑦ 门道出处
- 口碑问题天然是跨域问题（产品/客服/物流/宣传各占一段），单点视角永远归因不全；周报用三维交叉把「口碑」从评价区的分数变成全军团可认领的行动清单——口碑数据是质检与客服运营的交叉产物。
