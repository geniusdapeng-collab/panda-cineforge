# 周经营分析报告

## 何时调用
- cron 每周一 07:00：常规周报。
- 大促结束后 T+2：自动生成大促专项复盘（口径与周报一致，另附大促目标达成对照）。
- 老板手动发起任意时间窗的自定义复盘。

## 输入契约
- 本周 SKU 级损益表（sku-pl T+1 核算结果）。
- 生命周期打标变化记录（sku-lifecycle 阶段迁移事件）。
- 预算目标与拆解值（target-breakdown / budget-watch）。
- 事件库围栏触发流水（auto/review/block 全量）。
- 口碑数据（差评、评分、退货原因）。

## 执行步骤
1. **数据汇总**。动作：汇总本周损益、生命周期、口碑三类数据，锁定数据快照。产出物：周报数据集。回执：快照哈希写入事件库，保证"当时看到的就是这份数"。
2. **五维偏差对比**。动作：GMV/毛利/广告效率/库存/口碑五维度对比上周与预算目标，输出偏差表。产出物：五维偏差表。
3. **TOP5± 提取**。动作：按改善/恶化金额排序各取 TOP5，每项附初步归因（引用事件 ID）。产出物：TOP5 清单。
4. **围栏触发统计**。动作：统计本周 auto 放行多少条、review 多少条（批准/驳回比）、block 拦了什么（按 rule_id 分布）。产出物：围栏战报。
5. **分发与归档**。动作：推送老板与各作战军军长；整改建议以任务卡片进对应班组队列；全文归档组织记忆 pattern 类。产出物：周报文档+任务卡。回执：送达回执与归档 ID。

## 边界与围栏
- 只读分析：整改建议不直接执行，一律以任务卡进班组队列由对应技能承接。
- 报告涉及 PII 的明细数据走 **R22** 脱敏网关。
- 引用数据必须来自锁定快照，禁止事后改数；口径变更须在报告中声明版本。

## 与其他技能的协作
- 数据源：sku-pl、sku-lifecycle、budget-watch、target-breakdown。
- 恶化项自动挂 anomaly-attribution 深度归因任务。
- 归档供 decision-brief 案例回忆（pgvector 语义检索）。

## 验收用例
- 给定一周模拟数据：周报应含五维偏差表、TOP5± 项、围栏触发统计三节，每条结论可点击溯源到原始事件。
- 大促专项：T+2 自动产出，含大促目标 vs 实际达成对照。
