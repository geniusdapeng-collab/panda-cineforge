# 交接班管理

## 一、何时调用
- cron 每日 08:00/18:00/22:00 三个交接时点生成交接单。
- 战备模式切换（promo-war-room 启停）强制全量交接。
- 未签收超时（30 分钟）自动升级。

## 二、输入契约
- 各班组在途事项数据（未完成工单/挂起审批/进行中断点/监护中风险项，含状态/优先级/下一步/截止时限）。
- 交接双方身份与班次表；IM 触达与升级通道。
- 五元事件库签收留痕通道（哈希链）。

## 三、执行步骤
1. **交接单生成**：动作=自动提取本班次在途事项清单，逐条标注状态/优先级/下一步动作/截止时限；P0/P1 事项置顶并附上下文链接（事件链哈希）；产出物=交接单；回执=单据事件 ID。
2. **交班方签收**：动作=交班方确认"已交代"，签名入五元事件；产出物=交班签收记录；回执=哈希链事件 ID。
3. **接班方签收**：动作=接班方确认"已接到"，双向签收闭环；产出物=接班签收记录；回执=哈希链事件 ID。
4. **超时升级**：动作=30 分钟未签收→提醒；60 分钟→升级双方班长；监护中 P0 事项未签收前交班方不得离岗（系统层面保持告警通道）；产出物=升级记录；回执=触达回执。
5. **质量追踪**：动作=漏交接导致的断点自动归因到交接环节（反哺 incident-postmortem）；产出物=归因记录；回执=复盘单据号。
6. **周报**：动作=交接完备率/漏交率周报；产出物=周报；回执=归档事件 ID。

## 四、边界与围栏
- 签收只确认"信息已传达"，不转移裁决权：挂起审批仍在 review-console 等老板。
- 电子签收记录不可篡改（哈希链 append-only）。
- 交接单不含超权限数据（R22 数据密级思路：跨班组事项按密级摘要化）。
- 高危事项交接超时升级而非视为已交接（R30 超时纪律）；系统故障时降级为 IM 消息交接并事后补录。

## 五、与其他技能的协作
- 班次源：night-ops-suite（08:00 夜班交班）、promo-war-room（战备班强制交接）。
- 消费方：incident-postmortem（漏交接归因）、door-open-check（夜班挂起事项交接核验入开工检查）。

## 六、验收用例
- 正常路径：夜班遗留 1 个 P1 待审批与 2 个在途工单 → 08:00 交接单含三项完整上下文。
- 异常路径：接班方 30 分钟未签收 → 触发提醒；60 分钟 → 升级班长且 P1 事项告警保持。
- 围栏触发：跨班组事项含高密级数据 → 摘要化呈现，原文不可见。

## 七、门道出处
- 门道⑨组织与人效（5.2 补强裁决改标）：三班轮转的系统最怕"接缝处掉事"——夜班挂了审批白班不知道、白班断点夜班重复踩；传统交接靠微信群留言，漏交接是断点最大来源之一；双向电子签收把交接从"群里喊一声"变成"签收单上画押"，接缝从此可审计。
