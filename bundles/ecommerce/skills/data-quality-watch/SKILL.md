# 数据质量巡检

## 一、何时调用
- cron 每日 04:00 全量质检（T+1 核算开工前）。
- 数据接入异常事件（API 报错/字段变更/拉取为空）即时触发。
- sku-profit-ledger 核算异常率超阈值触发专项溯源。

## 二、输入契约
- 各平台数据管道（订单/账单/库存/广告/汇率源）与接入层适配器日志。
- 五维质检规则集（版本化）；平台账单期次日历与各源延迟基线。
- 冲正分录写入通道（append-only 账本）。

## 三、执行步骤
1. **五维质检**：动作=逐项判定——**完整性**（应有订单量 vs 实有、账单期次缺漏）、**准确性**（订单金额与平台账单勾稽差、库存数与后台比对漂移）、**一致性**（同一订单多源冲突、SPU 主档与平台链接属性不一致）、**时效性**（订单同步延迟/广告消耗延迟/汇率源断更）、**唯一性**（重复订单/重复扣费）；产出物=质检结果集；回执=逐项判定明细。
2. **命中分级**：动作=影响核算的 P1（阻断该数据域当日核算并告警）vs 影响展示的 P2（记录）；产出物=分级事件卡；回执=阻断记录。
3. **溯源定位**：动作=异常沿数据管道回溯到接入环节（API 变更/适配器失效/映射配置错误）；产出物=溯源报告+修复任务卡；回执=管道日志引用。
4. **修复验证与补数**：动作=修复后触发受影响时段数据重拉与重算，账本以冲正分录修正留痕（不直接覆盖）；产出物=冲正分录；回执=重算事件 ID。
5. **质量周报**：动作=各平台数据健康分/异常 TOP 类型/修复时长，反哺接入层适配器迭代；产出物=周报；回执=归档事件 ID。

## 四、边界与围栏
- 质检不静默修数：任何数据修正走冲正分录且留痕（append-only 哈希链）。
- 影响核算的异常宁可阻断当日核算也不让脏数据入账（未核算可信前禁止下游动作）。
- 平台侧数据错误区分"我方接入问题"与"平台数据源问题"，后者走对账争议线；质检规则版本化。
- 质检数据涉 PII 的按 R22 脱敏网关处理。

## 五、与其他技能的协作
- 守护对象：sku-profit-ledger（账本）、全域围栏判定（数据是判定地基）。
- 交叉验证：ai-tour（数据层抽检互证）、inspection-suite（接入异常事件源）。
- 修复执行：接入层适配器owner 技能；断点回接 incident-postmortem。

## 六、验收用例
- 正常路径：某平台 API 字段变更致当日订单金额集体错位 → 阻断该域核算、P1 告警并溯源定位到适配器映射配置。
- 异常路径：修复后重算 → 生成冲正分录而非直接覆盖，原错位记录可回溯。
- 围栏触发：汇率源断更 → 时效性命中，涉重定价的下游动作暂停并告警。

## 七、设计出处
- 来源：场景·13 平台数据归一化质量——门道⑧"算清每个 SKU 的账"的隐含前提是源数据是对的；"报表没更新靠人肉排查、平均停摆 1–3 天"证明数据质量是隐形地基；五维质检让地基沉降在裂到账本之前被发现。
