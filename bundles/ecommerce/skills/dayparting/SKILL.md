# 分时调价谷峰出价

## 一、何时调用
- cron 每周基于近 28 天数据重算分时模板；大促/直播日生成临时分时模板。
- 转化时段结构突变事件驱动。

## 二、输入契约
- 平台×店铺近 28 天分时数据（24 小时×7 天的 CTR/CVR/CPA/竞争热度）。
- 业务日历（大促日/直播场次/平台流量活动）、在用的分时模板版本。

## 三、执行步骤
1. **拉分时数据**：动作=按平台×店铺拉取近 28 天分时数据，剔除节假日与异常日防污染；产出物=清洗后分时数据集；回执=数据快照哈希+剔除清单。
2. **算系数曲线**：动作=计算每小时转化效率系数（CVR/CPA 归一化）与流量成本系数（CPC/竞争热度），两系数合成谷峰出价曲线：高效时段上浮（抢量）、低效时段下调（守 ROI）、无效时段暂停；产出物=24h×7d 出价系数模板；回执=系数计算口径与曲线图。
3. **叠加业务日历**：动作=大促日/直播场次/平台活动时段生成独立模板，不污染常规模板；产出物=临时模板；回执=模板作用域与有效期记录。
4. **下发执行**：动作=模板下发至各平台计划（直通车分时折扣/千川时段预算/PPC 分时规则）；产出物=下发指令；回执=各平台设置回执。
5. **过闸校验**：动作=分时系数调整幅度单次 >30% 的时段转 review（R4 思路）；夜班时段（22:00–08:00）动作遵守 R16 白名单；产出物=过闸记录；回执=RuleImpact 事件。
6. **滚动校准**：动作=每周滚动重算，模板变更留痕可回滚；最低 7 天观察窗，不因单周波动频繁改模板；产出物=版本记录；回执=版本号+回滚回执。

## 四、边界与围栏
- 绑定 R4（系数/预算调整幅度>30% 必审）、R16（夜班白名单自治）、R17（夜班调价≤3% auto 越线挂起）。
- 绝不做什么：绝不让分时模板绕过 acos-fuse 保险丝（亏损时段的"高效"不予上浮）；绝不在直播场次期间用常规模板覆盖 live-traffic-boost 实时联动；绝不用不足 7 天的数据改模板。

## 五、与其他技能的协作
- 消费方：ztc-campaign、qianchuan-campaign、amz-sp（分时模板下发）。
- 协同：ads-autopilot（白名单内分时微调）、live-traffic-boost（场次期间让位）、ads-budget-pacing（节奏加权）。

## 六、验收用例
- 正常路径：输入 28 天分时数据 → 输出 24h×7d 出价系数模板，标注谷峰时段。
- 日历路径：某大促日生成独立模板，常规模板数据不被污染。
- 围栏路径：单周波动触发的改模板请求 → 拒绝（不足 7 天观察窗）。

## 七、门道出处
- 门道⑤预算按峰谷联动：同样预算在不同时段效率可差 2–3 倍，人工分时模板一年不改一次；数据驱动滚动分时出价是零风险纯收益的"捡钱"技能。
