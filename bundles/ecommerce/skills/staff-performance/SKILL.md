# 数字员工绩效评议

## 何时调用
- cron 每周日 20:00：周度评议；每月末：月度评议。
- 事件驱动：某员工连续触发 block 3 次时即时评议。
- 老板手动对任意员工发起临时评议。

## 输入契约
- 事件库计量数据：各数字员工本周期任务量、一次通过率、review 驳回率与驳回原因分布、block 触发记录。
- token 成本：model-router 逐事件计量的模型调用费用。
- 岗位基线：各岗位四维指标的基准值（行业 Bundle 默认+客户校准）。
- 改进历史：上期"观察"档员工的改进措施与本期验证结果。

## 执行步骤
1. **计量提取**。动作：从事件库提取各员工本周期全部计量数据，剔除测试事件。产出物：计量宽表。回执：统计口径与事件区间留痕。
2. **四维评分**。动作：对照岗位基线打分——质量（一次通过率/驳回率）、效率（任务量/时延）、成本（token/任务）、合规（block 次数）。产出物：四维雷达评分。
3. **四档评定**。动作：综合分映射"优秀/合格/观察/待汰换"四档；连续 2 周观察自动升待汰换候选。产出物：评定表。
4. **改进建议**。动作：观察档附具体改进项——调 prompt/换模型路由档位/修 SOP 条目，每条注明预期改善指标。产出物：改进清单。
5. **报告推送**。动作：评议报告推老板；待汰换档自动触发 staff-replace-diagnosis。回执：报告 ID 与后续路由记录。

## 边界与围栏
- 评议结果仅为建议：任何配置变更（prompt/模型/权限）经人工确认后生效；变更超时未处理按 **R30** 升级而非自动执行。
- 评议依据全部来自事件库客观计量，不采信任何主观描述与自评。
- 计量数据可回放：每条评分能溯源到原始事件清单。

## 与其他技能的协作
- 下游：待汰换档 → staff-replace-diagnosis；改进项涉及 SOP → sop-forge。
- 输入：model-router（成本）、事件库（全部计量）。
- 汇总：月度评议结果供 board-report 军团运行章节引用。

## 验收用例
- 模拟某刊登员工一周 200 任务、驳回率 18%（基线 8%）：评"观察"档，并定位驳回主因（如类目属性错填占 60%），附修 SOP 建议。
- 连续 block 3 次：当日触发即时评议，不等周日。

## 门道出处
- 来自门道⑨组织与人效：绩效→汰换闭环是数字军团管理的核心机制。没有客观计量的军团就是 82 个黑箱，本技能让"带数字团队"第一次有了可量化、可审计的抓手。
