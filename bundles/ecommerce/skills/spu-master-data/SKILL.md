# 全球商品主数据治理

## 何时调用
- 新品建档时执行（建档入口强制走本技能）。
- cron 每周日 02:00：全量体检。
- 事件驱动：发现同品多条目冲突、成本字段缺失、各平台属性不一致时即时治理。

## 输入契约
- 新品资料：基础属性/成本档案/供应商/合规证照/目标平台清单。
- 存量商品库：全部 SPU/SKU 档案及平台映射关系。
- 成本价卡与供应商档案（purchase-order-auto / supplier-scorecard）。
- 合规证照库（compliance-sentinel 证照台账）。

## 执行步骤
1. **SPU 建档**。动作：建立一品一档——基础属性、成本档案、供应商、合规证照、多平台映射五区；分配全局唯一 SPU ID。产出物：SPU 主档。回执：建档事件+字段完整性校验结果。
2. **SKU 挂载**。动作：各平台 SKU 挂到 SPU 主档下；平台差异字段（类目属性/标题/价格）单独管理并登记映射。产出物：映射关系表。
3. **每周体检**。动作：三查——查重（同品多档，按属性相似度聚类）、查缺（成本/合规字段缺失）、查冲突（各平台属性不一致）。产出物：体检报告。
4. **治理清单**。动作：生成合并/补全/纠错清单进 review；批准后执行并留痕。产出物：治理工单。回执：每条治理动作的 before/after。
5. **变更广播**。动作：主档任何变更以事件广播至所有关联业务技能（刊登/损益/库存/广告）。回执：广播事件 ID 与各技能确认回执。

## 边界与围栏
- 成本字段按 RLS 行级权限脱敏展示；任何导出含 PII 或成本明细走 **R22** 脱敏网关。
- 主档合并/删除必人工确认，系统不自动并档。
- 主档是所有损益核算的唯一事实源：禁止业务侧私自建成本副本，发现副本数据一律以主档为准并告警。

## 与其他技能的协作
- 下游事实源：sku-pl（成本基线）、listing-factory（刊登数据源）、sku-lifecycle（阶段打标挂载）。
- 变更广播消费方：listing-factory（同步改链接）、pricing-matrix（成本变更重算）。
- 体检输入：supplier-scorecard（供应商信息）、compliance-sentinel（证照有效期）。

## 验收用例
- 构造同一商品在三个平台三条独立档案：体检识别为同品并生成合并建议；合并批准后损益核算自动归集到同一 SPU。
- 成本字段缺失的 SKU：列入查缺清单并阻断其补货流程联动（通知 sku-pl 标记）。
