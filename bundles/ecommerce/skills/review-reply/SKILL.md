# 评价回复多语言

## ① 何时调用
- 新评价产生事件触发：好评 T+24h 内回复；中差评在 review-defense-window 处置方案确定后回复。
- cron 每日扫描未回复存量评价。

## ② 输入契约
- 评价原文（多语言站点）；店铺品牌语气库；review-defense-window 处置结论（差评回复前置）；多语言双检管线（cs-multilang）；敏感词库与隐私脱敏规则。

## ③ 执行步骤
1. **评价分类**：好评（感谢+品牌强化）/中评（认领问题+说明改进）/差评（先线下处置后公开回应）。产出物：分类标签。回执：差评无处置结论不得回复。
2. **个性化生成**：按品牌语气库生成，引用买家提到的具体细节，拒绝模板感。产出物：回复草稿。回执：草稿与评价 ID 绑定留痕。
3. **差评回复四纪律**：不辩解不争辩、承认体验落差、说明已采取动作、引导线下通道；内容与处置方案一致，不承诺超出方案的补偿。产出物：纪律自检表。回执：涉承认质量缺陷的表述触发 R28 人审。
4. **多语言适配**：按站点语种母语级生成，回译双检保语义。产出物：双检记录。回执：回译偏差挂起人审。
5. **合规校验**：不含诱导改评表述/不含隐私信息（订单细节脱敏）/过敏感词库。产出物：校验通过记录。回执：恶意评价公开措辞经合规审。
6. **发布与留痕**：回复内容+引用评价 ID+关联工单 ID 三链入事件库。产出物：发布回执。

## ④ 边界与围栏
- R28（review）：评价回复涉承认质量缺陷必人审；白名单内好评回复可 auto。
- R22（review）：回复中买家信息脱敏，不披露个人信息。
- 禁止诱导改评表述；禁止承诺超出处置方案的补偿。

## ⑤ 与其他技能的协作
- 前置：review-defense-window 处置结论；语种能力：cs-multilang 双检管线；素材反哺：review-asset-mining（高频问题进入回复知识）；质检：service-qc。

## ⑥ 验收用例
- 英语站点一条提及「尺码偏小」的中评 → 生成引用该细节的英文回复（含改进说明与选购建议）、显示回译双检记录；好评类回复走 auto 白名单。
- 差评回复草稿含「我们承认产品存在质量缺陷」→ R28 拦下人审，RuleImpact(R28, review)。
- 回复草稿含买家订单号 → 脱敏校验拦截，不得发布。

## ⑦ 门道出处
- 报告一·回评环节：评价回复是公开的品牌表达，影响后续买家转化——评价区是「后来者先看的地方」，一条妥善的差评回复能把差评杀伤力转化为一半的信任建设；多语言+去模板化让回评从体力活变成品牌资产。
