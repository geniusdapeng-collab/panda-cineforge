# 平台活动报名

## 一、何时调用
- cron 每日 06:00 扫描 13 平台活动日历与报名窗口。
- 新活动公告发布事件驱动即时适配评估。
- 大促（双11/618/黑五/Prime Day/会员日）T-45 天自动生成大促报名作战计划。

## 二、输入契约
- 全平台活动日历库（活动名/平台/报名窗口/门槛条件/费用/历史效果）。
- 店铺门槛数据（评分/动销/库存深度）、SKU 损益数据（毛利/库存/退货率，源自 sku-profit-ledger）。
- 平台报名通道（L1 官方 API 优先，无 API 走 L3 确定性剧本）。

## 三、执行步骤
1. **日历维护**：动作=抓取各平台活动公告，更新日历库（窗口/门槛/费用）；产出物=活动日历增量；回执=抓取快照哈希。
2. **适配评估**：动作=窗口开启时逐活动核验店铺门槛×SKU 适配——毛利是否扛得住活动价、库存能否撑住预估流量；产出物=适配 SKU 清单；回执=门槛核验明细。
3. **毛利测算**：动作=逐 SKU 做活动价毛利测算并附敏感性（退货率/广告占比上浮情景），过 R2 毛利红线校验；产出物=测算表；回执=重算事件 ID。
4. **方案送审**：动作=生成报名方案（报哪个活动/哪些 SKU/活动价/备货联动需求推送 promo-stockup）进 review；产出物=审批卡片；回执=review-console 单据号。
5. **执行报名**：动作=审批通过后执行报名动作；产出物=报名回执；回执=平台受理凭证。
6. **追踪复盘**：动作=审核结果追踪（通过/驳回归因），活动后效果复盘（流量/转化/毛利 vs 预估）回写日历库历史效果字段；产出物=复盘记录；回执=日历库版本号。

## 四、边界与围栏
- 绑定 R2（活动价不得击穿毛利红线：售价 < 货品成本×1.15 物理 block，平台要求破价的场次放弃或升级人工裁决）。
- 绑定 R8（新平台首次报活动必审，无 auto 通道）。
- 活动保证金缴纳等大额支出必人工（R20 大额支出 review 思路）。
- 不为冲 GMV 报明知亏损的场次；毛利测算必须附敏感性情景，缺项方案不得送审。

## 五、与其他技能的协作
- 数据：sku-profit-ledger（毛利测算）、promo-stockup（备货联动）。
- 执行：listing 刊登技能（活动价上刊过 R1 单日降价≤10% 闸门）。
- 复盘：效果数据回写供 promo-war-room 战备与 multi-shop-matrix 引用。

## 六、验收用例
- 正常路径：Prime Day 报名窗口开启 → 当日输出适配 SKU 清单（含各 SKU 活动价毛利测算），报名动作停在人工确认。
- 异常路径：活动公告抓取失败 → 标「未核实」，日历库不更新，写异常事件。
- 围栏触发：某 SKU 活动价击穿毛利红线 → R2 block 并输出"放弃该 SKU 或升级人工裁决"说明；新平台首报 → R8 强制 review。

## 七、设计出处
- 来源：报告一·活动报名环节——平台活动是免费流量主入口，但 13 平台日历各异、门槛各异、错过窗口等一年；日历库+门槛自动核验+毛利闸门让"应报尽报、报必赚钱"成为纪律，直接服务门道②免费流量结构。
