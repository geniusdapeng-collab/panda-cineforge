# 平台结算追踪

## 一、何时调用
- cron 每日 07:30 按结算日历跑应回款预测。
- 平台打款到账事件触发核销；应到账逾期 >24h 触发异常追查。

## 二、输入契约
- 13 平台×各店铺结算周期、放款条件、冻结规则（亚马逊 14 天/拼多多 T+1/天猫确认收货后/速卖通放款条件等）。
- 银行与收款通道流水、平台打款单、对账完成状态。
- 各平台预留金（reserve）余额与变动记录。

## 三、执行步骤（操作手册）
1. 结算日历维护：13 平台×店铺建模结算周期、放款条件、冻结规则，版本化。
2. 应回款预测：每日输出未来 14 天分平台分币种应回款现金流表，API 供 cash-sandbox 直接取数。
3. 到账核销：银行/通道流水 × 平台打款单 × 对账完成状态三方核销，差额定位到具体结算期。
4. 异常追查：逾期未到账分级——平台延迟（跟踪）/账户审核（告警+资料准备）/资金冻结（P0 升级 appeal-kit）。
5. 冻结与预留金监控：预留金余额与释放预测，冻结比例突增即时告警。
6. 回款健康月报：回款周期趋势、异常率、各平台资金占用成本。

## 四、边界与围栏
- 到账核销差异冲正必人工（对齐 R23 资金纪律）。
- 资金冻结类异常只做告警与证据归集，申诉动作交 appeal-kit。
- 预测模型参数变更留痕；大额逾期触发现金流预警联动 cash-sandbox（P0 口径）。

## 五、与其他技能的协作
- 对账完成信号来自 multi-platform-reconciler；回款预测供血 cash-sandbox；冻结事件升级 appeal-kit 并联动 fx-hedge-advisor 结汇排程。

## 六、验收用例
- 正常：某亚马逊店铺应回款日 +2 天未到账，分级告警并输出该店预留金变动与账户审核状态。
- 接口：回款预测表可被 cash-sandbox 以 API 形式直接取数，字段含平台/币种/金额/预计到账日/置信度。

## 七、门道出处
- 非★技能（门道⑥供血模块）。来源：场景·各平台结算周期与回款管理（回款是"赚到的钱"和"能用的钱"之间最后一段路）。
