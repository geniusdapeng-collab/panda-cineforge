# 违规动作阻断 ★

## 一、何时调用
- 任何 Agent/人工发起的写动作经过围栏引擎判定即触发（前置拦截）。
- 违规关键词/模式命中即时 block；每周输出违规企图审计报告。

## 二、输入契约
- 待判定写动作（动作主体/目标/参数/上下文）；违规规则库版本。
- 组织记忆 forbidden 类条目；历史违规企图记录。

## 三、执行步骤（操作手册）
1. 违规规则库加载四大类：刷单类（测评下单/礼品卡换评/买空竞品）、评价操纵类（删差评请求/好评返现卡/合并僵尸 listing 评论）、虚假宣传类（伪造认证/虚标参数/假倒计时）、资金违规类（低报货值/拆单避税）。
2. 动作语义判定：不只匹配关键词，判定动作实质——如"联系买家改评价送券"识别为评价操纵。
3. 三级处置：命中 block 级→物理阻断+forbidden 记忆写入+责任人告警；命中 review 级→审批卡片附违规风险说明；灰度模糊→宁可错杀按 block 处理。
4. 阻断留痕：RuleImpact[] 完整记录（rule_id/version/result）。
5. 企图审计：每周输出违规企图 TOP 榜（谁/什么动作/动机上下文），连续企图触发人员风险预警。
6. 规则库迭代：新变种话术/手法经人工确认后入库，基线单调守卫——只加严不放松。

## 四、边界与围栏
- 本技能即 R11 的执行主体；阻断决定全量留痕可回放（dry-run 可验证）。
- 不误伤合规动作："Request a Review 官方按钮"与"操纵评价"必须在规则库中明确区分。
- 规则收紧即时生效，放宽必须走版本评审；高危审批超时按 R30 升级而非放行。

## 五、与其他技能的协作
- 作为 fence-engine 行业规则包执行面服务全部技能；违规线索反哺 compliance-sentinel；企图审计供 risk-radar 与组织人效域；评价类边界与客服域 R9/R28 协同。

## 六、验收用例
- 围栏：模拟"给留差评买家补 ¥50 请其删除评价"的动作，被物理阻断、写入 forbidden 并告警。
- 放行：官方 Request a Review 批量触发正常放行，不误伤。

## 七、门道出处
- ★门道⑩/R11 固化技能：违规诱惑是"短期有效"、代价是"账号清零"——这条防线必须是物理的而非劝诫的。
