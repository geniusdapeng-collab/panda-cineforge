# 物流异常处理

## 一、何时调用
- 物流轨迹异常实时触发：停滞 >48h、签收破损、错分、超期未妥投、清关延误。
- 快递商/货代异常通告入站，触发批量影响面扫描。

## 二、输入契约
- 全渠道运单轨迹流、批次/渠道归属、订单货值。
- 物流商合同 SLA 与索赔条款；买家沟通状态（是否已诉）。

## 三、执行步骤（操作手册）
1. 异常识别与分级：延误类 P2 / 破损丢件类 P1 / 清关扣押与整批延误 P0。
2. 影响面归集：同批次、同渠道受影响订单全量列出，标记已诉买家与未察觉买家。
3. 双线处置：物流商侧自动生成核实/索赔工单（附运单号、货值、时限要求）；买家侧未诉先安抚（联动客服域主动触达）。
4. 索赔跟踪：按物流商 SLA 倒计时，超期未赔升级并计入该商 KPI 扣分。
5. 补救决策：补发/退款/补偿按金额过 R5/R10 闸门；P0 批量事件生成统一处置预案。
6. 结案归档：异常类型×渠道×物流商三维统计，反哺快递与货代选型矩阵。

## 四、边界与围栏
- R5：单笔退款/补发货值 ≥¥1000（或 ≥$200）必 review；R10：对外补偿 ≥¥500 必人审。
- 清关扣押涉申报不符等合规问题，立即转 compliance-sentinel，不擅自处理。
- 索赔金额以合同与货值凭证为准，不做情绪化加价；不虚假申报损失（R11）。

## 五、与其他技能的协作
- 轨迹源取 last-mile-track；买家触达联动客服域 logistics-query；统计反哺 cn-express-optimize/freight-forward 选型；赔付金额落 sku-profit-ledger。

## 六、验收用例
- 正常：某航班延误影响 47 票，批量归集受影响订单、生成货代核实工单与买家安抚任务，按清关/在途分类。
- 围栏：一单 ¥1,200 破损补发触发 R5 review，未批不执行。

## 七、门道出处
- 非★技能。来源：报告一·物流异常环节（滞留/破损/丢件/错分跟进是客服与仓储三不管地带，人工漏单率高）。
