# 异常归因分析

## 何时调用
- 事件驱动：biz-dashboard 红灯项自动生成归因任务。
- 老板/军长手动圈选任意指标异动发起追问（如"昨天 GMV 为什么掉"）。
- 周报 TOP5 恶化项自动挂深度归因。

## 输入契约
- 异常指标定义：指标名、时间窗、基线值、当前值。
- 指标树模型：GMV=流量×转化×客单；毛利=GMV−9 大扣减科目；退货率/ACoS 等分解口径。
- 五元事件库同期流水：改价/调广告/换主图/差评聚集/竞品动作等全量留痕。
- 外部信号：竞品数据卡（competitor-product-track）、平台规则变更（platform-rule-track）。

## 执行步骤
1. **锁定异常**。动作：确认指标、时间窗、异动幅度与统计显著性（排除正常波动）。产出物：异常确认单。
2. **指标树下钻**。动作：沿分解口径逐层比对同期值，定位贡献最大的子项（如 GMV 下滑中流量贡献 80%）。产出物：下钻路径表。
3. **事件交叉关联**。动作：在异常时间窗内检索相关事件，建立"事件→指标变化"时间先后与量级匹配。产出物：候选证据链。回执：引用事件 ID 全量列出。
4. **归因结论**。动作：输出主因+贡献度占比+诱因排序，标注置信度；证据不足时明写"疑似"，给出补数建议。产出物：归因报告。
5. **处置选项**。动作：给 1–3 个处置选项（各附预期影响）进 review-console。回执：归因报告 ID 与审批路由记录。

## 边界与围栏
- 只产出结论与建议：处置动作由对应业务技能执行，本技能不落写操作。
- 证据不足必须标"疑似"并说明缺什么数据，禁止编故事凑结论。
- 结论引用的所有事件 ID 可回放，数据口径与快照哈希一致。

## 与其他技能的协作
- 触发源：biz-dashboard 红灯、weekly-ops-report 恶化项。
- 证据源：competitor-product-track（竞品动作）、sku-pl（损益科目）。
- 处置路由：定价类→pricing-matrix，广告类→ads-autopilot，口碑类→review-defense-window。

## 验收用例
- 构造"昨日 GMV 环比 -22%"：输出形如"主因：A 店铺核心词自然排名 3→11（贡献 70%），诱因：竞品 B 前日降价 12%（证据：事件 #evt-xxx）"，置信度与证据链完整。
- 证据不足案例：输出"疑似"并列出需补数据，不得给出确定性结论。
