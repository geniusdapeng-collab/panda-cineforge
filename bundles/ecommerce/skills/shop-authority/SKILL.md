# 店铺授权与凭据管理

## 一、何时调用
- cron 每日 03:30 全量凭据巡检（有效期/可用性/权限范围）。
- 凭据调用失败事件即时触发失效处置；到期前 30/14/7 天三级预警。
- 新店铺接入/员工离职触发凭据增删审计；疑似泄漏事件触发应急流程。

## 二、输入契约
- 凭据台账（14 店铺×13 平台 API token/开发者密钥/广告账户授权/ERP 对接凭据，加密存储）。
- 凭据依赖图谱（哪条技能依赖哪个凭据）；探活接口清单（只读）。
- 人员在职状态与权限变更事件。

## 三、执行步骤
1. **凭据台账建档**：动作=全量凭据加密建档，明文凭据永不出库；产出物=台账版本；回执=加密入库回执。
2. **有效期三级预警**：动作=30 天 P2 提醒→14 天 P1 生成续期任务→7 天 P0 升级；逾期未续自动降级相关技能为只读防报错雪崩；产出物=预警单/续期任务卡；回执=推送与派单回执。
3. **可用性探活**：动作=每日只读接口轻量探活，失效即时定位影响面（依赖该凭据的技能清单）；产出物=探活报告+影响面清单；回执=探活回执，失败即事件。
4. **权限最小化审计**：动作=逐凭据核对授权范围 vs 实际所需（只需读订单的凭据不得带写权限），超权限凭据生成收紧任务；产出物=审计报告+收紧任务；回执=任务回执。收紧可 auto，放宽必人工审批。
5. **使用留痕**：动作=凭据调用全量入五元事件（谁/何时/调了什么/为何）；产出物=调用日志；回执=哈希链事件 ID。
6. **泄漏应急**：动作=疑似泄漏触发一键吊销+轮换流程与影响面追溯；产出物=应急处置卡；回执=吊销/轮换凭证。

## 四、边界与围栏
- 绑定 R22（凭据按最高密级管理，任何 Agent 不得读取明文，调用经安全网关代理）。
- 绑定 R23（吊销/轮换属安全禁区高危动作，人工确认后执行）。
- 绑定 R30（高危审批超时升级而非放行，续期审批不过期自动生效）。
- 离职人员名下凭据 24h 内完成回收核验，逾期 P0 升级。

## 五、与其他技能的协作
- 消费方：全部依赖平台 API 的技能（探活结果驱动只读降级）。
- 联动：shop-health-check（凭据有效性入体检资金线）、ai-tour（静默失效探针）、incident-postmortem（凭据类断点免疫动作回接）。

## 六、验收用例
- 正常路径：某平台 token 14 天后到期 → 生成 P1 续期任务并列出依赖该凭据的 6 个技能清单。
- 异常路径：凭据调用连续失败 → 即时降级相关技能为只读并推送失效影响面。
- 围栏触发：吊销请求 → R23 人工确认后执行；续期审批超时 → R30 升级不放行。

## 七、设计出处
- 来源：场景·14 店铺凭据管理——凭据是系统运行的钥匙串："授权过期导致 ERP 停摆 3 天"是真实高频事故，凭据超权限是封号潮账号关联团灭的隐形引信；台账+三级预警+最小化审计让钥匙串从没人管的抽屉变成有哨兵的保险柜。
