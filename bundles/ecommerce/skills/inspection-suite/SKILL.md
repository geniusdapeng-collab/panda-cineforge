# 巡检套件

## 一、何时调用
- cron 全天候分频巡检：价格线 2h/库存线 4h/广告线 2h/客服线 1h/合规线 4h；夜间按 R16 白名单节奏加密或降级。
- 任一检项命中阈值即时生成 P 级事件；大促战备期频次整体加密（promo-war-room 战备档）。

## 二、输入契约
- 五线检项包（行业 Bundle 默认阈值，客户 Patch 只收紧，版本化管理）。
- 各平台只读数据通道（价格/库存/广告/客服/合规数据源）。
- 派单通道（各域技能处置队列）与 IM 分级推送通道。

## 三、执行步骤
1. **五线检项加载**：动作=加载检项包——价格线（破价/倒挂/价保冲突/竞品降价）、库存线（断货风险/超卖/库龄越阈/负库存）、广告线（ACoS 越线/预算提前耗尽/异常点击/计划掉量）、客服线（响应超时/升级关键词未路由/满意度突降/会话积压）、合规线（违规预警/资质临期/差评聚集/绩效越限）；产出物=巡检任务集；回执=检项包版本号。
2. **分频执行**：动作=按各自频率只读采集与判定；产出物=命中事件流；回执=采集回执，数据断流标「未核实」不误报。
3. **P 级分级**：动作=命中事件按 P0（即时电话级）/P1（即时 IM）/P2（聚合日报）分级；产出物=分级事件卡；回执=分级依据记录。
4. **聚合防风暴**：动作=同源事件合并推送（30 个 SKU 同时破价合并为 1 张事件卡），单班次事件超阈值自动升聚合级别；聚合折叠不得吞掉 P0；产出物=聚合事件卡；回执=合并规则命中记录。
5. **一键派单闭环**：动作=事件卡直转对应域技能处置队列，处置状态回写；产出物=派单单；回执=处置状态回执。
6. **巡检周报**：动作=命中率/误报率/处置时长/复发率周报，反哺检项阈值迭代；产出物=周报；回执=归档事件 ID。

## 四、边界与围栏
- 巡检严格只读：任何写动作经派单由业务技能在各自围栏内执行，巡检自身无一写权限。
- 夜间频次调整遵守 R16 白名单纪律；P 级阈值行业 Bundle 定默认、客户 Patch 只收紧。
- 聚合折叠不得吞掉 P0；新增检项须 dry-run 验证误报率后上线。

## 五、与其他技能的协作
- 消费方：door-open-check（聚合视图复用本检项包）、shop-health-check（体检数据源）、night-ops-suite（夜间事件流）。
- 处置方：定价/库存/广告/客服/合规各域技能；复盘：incident-postmortem（断点→新检项回接）。

## 六、验收用例
- 正常路径：同一促销配置错误致 28 个 SKU 同时破价 → 合并为 1 张 P0 事件卡（非 28 条轰炸）并一键派单至定价技能。
- 异常路径：1 个客服升级关键词漏路由 → P1 即时推送。
- 围栏触发：数据断流时 → 标「未核实」不产生误报事件。

## 七、设计出处
- 来源：底座巡检中心行业检项包——14 店×13 平台的异常"每天必然发生、但 90% 不值得打扰人"；巡检套件的价值不在发现问题而在分级与聚合：让 P0 永远响得动、P2 永远不吵人，这是系统被长期信任的关键。
