# 夜班运营套件

## 一、何时调用
- cron 每日 18:00 生成夜班候选清单、22:00 进入自治窗口、08:00 窗口关闭、08:30 输出清晨决策包。
- 窗口内 P0 事件即时升级；老板/值班人"一键暂停"指令随时可发。

## 二、输入契约
- 各域提交的夜班拟办动作（调价/广告降档/差评处置/跟卖驱赶/补货催办）及预期围栏判定。
- R16 夜班自治白名单（版本化，含动作类型/幅度上限/适用店铺）。
- 五元事件库写入通道；值班人触达通道（IM/电话级）。

## 三、执行步骤（状态机）
1. **18:00 候选清单**：动作=汇总各域拟办动作，逐条标注预期围栏判定级别（auto/review/block）；产出物=候选清单；回执=清单事件 ID。
2. **白名单裁定**：动作=R16 白名单内动作（阈值内调价/预算降档/模板化客服应答）准入自治，名单外动作挂起待审——宁挂不错；产出物=自治准入表+挂起表；回执=RuleImpact 事件。
3. **22:00–08:00 自治执行**：动作=动作过围栏引擎三级判定后执行，全程五元事件留痕；仅许"防守性"动作（降档/止损/应答/告警），禁止"进攻性"动作（加预算/提价/报活动）；产出物=执行日志；回执=逐动作回执。
4. **异常治理**：动作=P0 事件（封店预警/资金冻结/重大舆情/R23 安全禁区熔断）即时电话级触达值班人，不等清晨；一键暂停 ≤60s 全局生效；任一 Agent 中断自动断点记录与续跑；产出物=升级记录/暂停回执/断点档案；回执=触达与恢复回执。
5. **08:30 清晨决策包**：动作=三栏归类——已完成（附回执）/待审批（附建议手势：一键批准/一键派单）/需介入（附上下文），P0/P1/P2 分级排序，合计 ≤20 条，超限自动聚合折叠且裁剪记录留痕；产出物=决策包卡片；回执=IM 触达回执，08:30 未读 09:00 升级。
6. **周报复盘**：动作=夜班自治率与误拦率周报，反哺白名单迭代；产出物=周报；回执=归档事件 ID。

## 四、边界与围栏
- 绑定 R16（白名单外动作一律挂起 review）、R17（夜班调价 ≤3% auto，越线挂起）。
- 绑定 R30（高危审批不过期自动放行，超时升级而非放行）、R23（安全禁区 P0 即时升级）。
- 白名单变更必人工审批且 dry-run 回放验证后生效。

## 五、与其他技能的协作
- 统辖：night-eu-us-watch、cs-night-shift 及各域夜班档位；决策包由 morning-briefing 消费。
- 交接：handover-manager（08:00 挂起事项签收）；战备：promo-war-room（战时白名单临时扩展）。

## 六、验收用例
- 正常路径：一夜 60 条事件（含 3 条名单外动作）→ 白名单内执行、3 条挂起，08:30 决策包三栏 ≤20 条且每条可溯源事件 ID。
- 异常路径：注入 P0 封店预警 → 即时电话级触达不等清晨；一键暂停 → ≤60s 全局生效。
- 围栏触发：夜班调价 5% → R17 越线挂起；名单外动作 → R16 挂起待审。

## 七、设计出处
- 来源：蓝本夜班电商化——候选清单管住"夜里该干什么"、白名单管住"夜里能干什么"、决策包管住"早上怎么交代"，三者缺一不可；≤20 条+分级排序把老板每天第一决策成本压到 5 分钟以内，这是夜班自治被信任的心理前提。
