# 经营仪表盘

## 何时调用
- cron 每日 06:00：T+1 数据就绪后全量刷新。
- 事件驱动：核心指标越限（退货率/ACoS/周转超阈值）时实时刷新并生成告警事件。
- 老板或军长手动打开看板时按最新快照呈现。

## 输入契约
- 数据大脑 T+1 多平台经营数据（经 RLS 行级隔离，多店铺/多小组互不可见）。
- 基线阈值配置：行业 Bundle 默认值 + 客户 Patch（只可收紧）。
- SKU 级损益数据（来自 sku-pl）、口碑数据（差评数）、现金流预测（cash-sandbox）。

## 执行步骤
1. **数据拉取与校验**。动作：从数据大脑拉取 T+1 数据，校验完整性（缺平台/缺店铺标"数据未齐"）。产出物：标准化指标宽表。回执：记录数据快照哈希。
2. **六指标计算**。动作：计算付费流量占比、ACoS/TACoS、库存周转天数、退货率、7 日差评数、8 周现金流缺口。产出物：指标值+环比/同比。回执：计算公式版本号入事件。
3. **红黄绿灯判定**。动作：与基线阈值比对，逐项标灯；绿灯项不推送（防信息过载）。产出物：灯态表。
4. **异常清单生成**。动作：仅汇总红黄灯项，按影响金额排序，生成 P0/P1 告警事件。产出物：异常清单。回执：告警事件 ID 回写。
5. **下钻服务**。动作：异常项支持一键下钻至 SKU/店铺/广告组层级，展示贡献度拆解。产出物：下钻视图数据。

## 边界与围栏
- 只读域：任何写动作（调价/降广告/补货）必须路由到对应业务技能执行，仪表盘自身不落任何写操作。
- 涉及订单/会员明细的展示走 **R22（数据导出 PII）** 脱敏网关。
- 阈值客户 Patch 只可收紧不可放宽，放宽请求一律拒绝并提示走行业 Bundle 升级流程。

## 与其他技能的协作
- 红灯项自动触发 anomaly-attribution 归因任务。
- 指标速览供 morning-briefing 引用；周度汇总供 weekly-ops-report。
- 数据源依赖 sku-pl（损益）、spu-master-data（主档口径）。

## 验收用例
- 构造某 SKU 退货率从 12% 跳至 31%：当日刷新应标红该 SKU、生成 P1 告警事件，且可下钻看到退货原因分布。
- 某平台数据未就绪：对应板块标"数据未齐"，不得用旧数据冒充 T+1。
